# Roadmap 进度总览设计

## 摘要

在 `docs/roadmap.md` 顶部增加“当前进度总览”和“版本进度表”，使维护者下次只读取 roadmap 就能判断项目当前版本、交付阶段、验证状态、阻塞项和下一步。现有版本目标、验收条件与长期方向继续保留，进度表只提供摘要和导航。

## 目标

- 打开 roadmap 后优先看到项目当前所处阶段，而不是先阅读全部版本规划。
- 统一表达版本、PR、CI、本地验证、阻塞项、下一步和更新时间。
- 区分本地已验证事实、远端已验证事实和仍待执行的发布动作。
- 为后续版本提供稳定、低维护成本的进度记录格式。

## 非目标

- 不把 roadmap 变成逐任务项目管理系统。
- 不复制完整发布验收记录、测试日志或 PR 描述。
- 不自动查询 GitHub 或在文档中伪装实时状态。
- 不修改版本范围、运行时能力、Schema、规则注册表或发布权限边界。

## 信息结构

### 当前进度总览

放在 roadmap 的导言和维护规则之后、版本详细规划之前，使用两列表格展示：

| 字段 | 含义 |
| --- | --- |
| 当前版本 | 正在交付的版本或里程碑 |
| 总体状态 | 使用统一状态枚举表示当前阶段 |
| Pull Request | PR 编号、草稿或正式状态，以及可点击链接 |
| CI | 已核验的支持环境结果及核验日期 |
| 本地验证 | 最新完整门禁统计及证据链接 |
| 当前阻塞 | 明确阻塞；没有时写“无技术阻塞” |
| 下一步 | 一个可执行的近期动作序列 |
| 最近更新 | 使用 `YYYY-MM-DD` 日期，说明状态的新鲜度 |

`v1.0.1` 的初始总体状态为 `待发布`、完成度为 `90%`：代码与本地验收完成；PR #1 为草稿；Ubuntu、macOS 与 Node.js 20、22、24 六组 CI 已通过；无技术阻塞；下一步为转正式评审、合并、创建标签、远端标签安装冒烟和 GitHub Release。

### 版本进度表

紧接当前进度总览，按版本一行展示：

| 列 | 含义 |
| --- | --- |
| 版本 | `v1.0.1`、`v1.1.0` 等版本标识 |
| 阶段 | 版本当前处于规划、实现、发布或完成阶段 |
| 完成度 | 粗粒度比例，用于快速比较，不作为精确工时指标 |
| 已完成 | 最重要的已交付结果摘要 |
| 下一道门禁 | 进入下一状态前必须完成的验收动作 |
| 状态说明 | 必要的边界或风险说明 |

初始版本行覆盖 `v1.0.1`、`v1.1.0`、`v1.2.0`、`v1.3.0` 和 `v2.0.0`。未开始版本不虚构完成度：规划内容已明确时可写 `0%` 和“规划中”。

## 状态契约

状态只使用以下枚举：

- `规划中`：范围已记录，但未进入实现。
- `进行中`：实现、测试或文档仍在推进。
- `代码完成`：本地实现和门禁完成，尚未进入或完成发布流程。
- `待发布`：目标提交远端验证完成，等待合并、标签或 Release。
- `已发布`：稳定标签和 Release 已完成，并通过远端标签安装验证。
- `阻塞`：存在明确外部依赖、权限或重复失败条件，无法继续推进。

完成度按版本交付阶段粗略记录：`0%`、`25%`、`50%`、`75%`、`90%`、`100%`。`100%` 只用于已发布版本；代码完成但未发布的 `v1.0.1` 使用 `90%`。

## 证据与维护规则

- PR、CI 和远端发布状态必须附核验日期；日期之后发生变化时，旧状态仍被视为历史快照，不是实时承诺。
- 本地验证链接到对应发布验收记录，不在 roadmap 复制长日志。
- “无阻塞”只表示当前没有已知技术或权限阻塞，不代表发布动作已获得授权。
- 每次版本状态跨越枚举阶段时，同步更新当前进度总览、对应版本行和详细版本段落。
- 已发布版本保留最终状态；当前进度总览始终指向正在交付的最新版本。
- 详细需求仍归属各版本正文；进度表不添加正文没有覆盖的新能力。

## 验收条件

- roadmap 顶部可在不阅读版本正文的情况下回答“当前版本、状态、PR/CI、本地验证、阻塞、下一步、更新时间”。
- `v1.0.1` 的进度值与 PR #1、六组 CI 和发布验收记录一致。
- 后续版本的状态与现有路线图范围一致，不提前声明实施或交付。
- 所有 Markdown 链接有效，表格在 CommonMark/GitHub Markdown 中可读。
- `node scripts/validate-marketplace.mjs` 和 `npm run validate` 通过。
- 不包含个人绝对路径、凭据、一次性临时路径或未授权发布声明。
