# v1.0.1 发布收口设计

## 摘要

`v1.0.1` 是 `v1.0.0` 之后的安全与稳定性补丁版本。本轮只收口已经进入 `main` 的 P0 安全加固、兼容性验证、版本声明和发布文档，不新增用户能力，不引入第三方依赖，也不执行标签、推送或公开发布。

## 目标

- 将路线图中属于 `v1.0.1` 的事项逐项归类为已完成、需要补充证据或明确后移。
- 只读核验远端 `main`、`v1.0.0` 标签和 GitHub Actions 验证状态。
- 对插件安装产物和脱敏隔离仓库执行本地发布前验证。
- 发现明确缺口时，先增加失败测试或可复现验收用例，再完成最小修复。
- 将公开版本、安装示例、变更日志、路线图和发布验收记录同步到 `1.0.1`。
- 交付通过完整本地门禁、可由维护者决定何时发布的干净变更集。

## 非目标

- 不实现 `config validate`、`config explain` 或配置初始化；这些能力保留在 `v1.1.0`。
- 不扩展 workspace 布局发现、SARIF、第二插件或外部系统集成。
- 不新增依赖，不申请新的网络或外部写权限。
- 不创建或移动 Git 标签，不推送，不创建发布，不修改远端仓库设置。
- 不为追求测试数量而增加没有明确风险场景的负向用例。

## 方案

采用最小发布收口方案。代码以当前 P0 实现为基线，先通过审计和隔离验证识别真实缺口；没有失败证据时不修改运行时。该方案保持 patch 版本的兼容边界，同时把发布证据和文档状态统一起来。

未采用仅文档发版方案，因为它不能证明插件缓存产物和隔离目标仓库可正常工作。也未采用扩大安全功能范围的方案，因为现有测试已经覆盖主要路径逃逸、符号链接、竞态替换、敏感内容和 Git revision 风险，额外功能应由新的失败证据驱动。

## 工作流

### 1. 状态审计

建立 `v1.0.1` 验收矩阵，对照路线图、CHANGELOG、CI 配置和最近提交，将每项要求标记为：

- 已由代码和自动测试证明；
- 需要补充本地或远端验证证据；
- 明确后移至 `v1.1.0` 或更晚版本。

远端核验保持只读。无法从当前权限或网络环境证明的状态必须明确记录为维护者发布前动作，不能推断为已经完成。

### 2. 隔离验证

本地验证至少覆盖：

- 完整 `npm run validate` 门禁；
- 从插件实际目录运行 `doctor`；
- 在隔离临时仓库中执行规则检查、影响分析和评审上下文生成；
- 使用隔离 Codex 配置目录验证 Marketplace 与插件安装产物能够被发现；
- 确认验证过程不会读取目标仓库外文件或执行外部写入。

临时资产放在系统临时目录并使用明确路径。验证脚本失败时保留可诊断输出；只有在失败能够复现产品缺口时才进入实现修改。

### 3. 最小修复

若审计或隔离验证发现缺口，按以下顺序处理：

1. 增加能够稳定复现问题的测试或验收用例；
2. 确认用例在当前实现上失败；
3. 修改最小范围的脚本、Schema 或文档契约；
4. 运行相关隔离测试和完整门禁；
5. 插件内容发生变化时使用 Plugin Creator 的 cachebuster 更新脚本刷新插件构建元数据。

不进行与失败场景无关的重构。

### 4. 版本与文档一致性

发布资产统一表达以下事实：

- 根包公开版本进入 `1.0.1`；
- 插件基础版本进入 `1.0.1`，cachebuster 仅表达插件缓存刷新时间；
- README 稳定安装示例固定到 `v1.0.1`；
- CHANGELOG 将当前安全与稳定性内容归入 `1.0.1`，保留新的空“未发布”区段；
- 路线图把 `v1.0.1` 标记为代码收口完成或发布待执行，并逐项记录证据；
- 发布验收文档区分已经验证的本地事实和仍需维护者执行的远端发布动作。

配置、输出契约或规则族没有变化时，不修改对应 Schema、规则注册表和评测资产。

## 错误处理与安全边界

- 网络、GitHub 或远端标签状态不可用时，记录为未核验，不绕过权限限制。
- 安装冒烟失败时先区分产品缺口、环境缺失和 Codex CLI 版本差异。
- 所有能力继续保持只读，不增加生产凭据、用户数据或外部写入路径。
- 发布说明不得声称未实际执行的远端操作或跨平台结果。

## 验收条件

- `npm run validate` 通过且没有测试失败。
- 三项插件命令在脱敏隔离仓库中产生符合既有契约的结果。
- Marketplace 和插件安装产物在隔离配置中能够被发现并通过 doctor。
- 根包、插件 manifest、README、CHANGELOG、路线图和发布验收文档的版本及状态一致。
- 所有运行时修改都有先失败后通过的测试或明确验收证据。
- 插件内容变化后 cachebuster 已通过 Plugin Creator 工具刷新。
- 工作区不包含任务无关修改；没有执行标签、推送、发布或远端写入。

## 发布者后续动作

本轮实现完成后，维护者仍需根据发布清单决定并执行远端 CI 复核、创建 `v1.0.1` 标签、推送标签、从远端标签进行干净安装以及发布公告。这些动作需要单独明确授权。
