# 安全设计

## 数据最小化

执行引擎只收集完成当前分析所需的 Git 路径、变更行、workspace 清单和安全 diff。敏感路径在进入规则、影响和评审上下文前统一过滤。

默认跳过：

- `.env` 及其变体。
- 私钥、证书、keystore 和签名文件。
- 名称包含 credentials 或 secret 的常见凭据路径。
- `.git`、依赖目录、构建输出和覆盖率产物。

单个配置或新增文本文件超过一 MiB 时不会作为普通分析输入。

## 权限边界

三个首发能力不需要网络、生产凭据或外部写权限。它们不会自动修复代码、发布 PR 评论、批准、合并、部署或回滚。

## 输出边界

- 确定性发现包含规则编号、最小证据和严重级别。
- 语义推断包含置信度；证据不足时进入问题列表。
- diff 上限默认为 120,000 字符，截断后明确提示继续按需读取相关源码。
- 模型评审是建议，必须与真实 CI 和人工审批结合。

未来接入代码托管、监控或需求系统时，应按权限拆分独立插件，并增加最小授权、人工确认与审计记录。
